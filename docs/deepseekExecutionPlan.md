# DeepSeek Goal 执行任务书：Toonflow 单人服务器二改

版本：2026-10-08 第一版。此文件是可开工执行计划；背景和审计证据见同目录 `serverDeploymentPlan.md`。两者冲突时，用户最新指示优先，其次本执行计划的最新范围和验收规模，再其次历史方案。

## 1. Goal 目标与已确认要求

在当前源码基础上，保留已可用的桌面供应商协议，完成单人服务器版的可靠媒体任务、MCP 画布控制、单账号登录、按天清理，以及隔离部署和小规模真实验收。不得用延长超时替代持久任务，也不得重写整个项目。

用户的日常方式：本机 Codex 通过 MCP 连接线上 Toonflow，以对话完成短剧工作流。用户愿意打开 Toonflow 网页；画布操作仍由网页执行，切到其他标签页正常运行时应可继续控制。浏览器冻结、电脑休眠无法保证执行，必须显示断连/恢复信息。不实现无网页画布引擎。视频任务受理后不依赖网页或 Codex 持续在线。

- 100 条只是常见批次示例，不是业务上限；允许更大批次、分次提交和持续追加。限制执行并发及单次传输大小，不把项目/批次数量硬编码为 100。
- 本轮批量验收缩小为 **10～20 次提交**；真实视频验收 **首轮总计最多 2 条**，优先 1 条，确有必要再使用第 2 条。不默认每个子任务各生成 2 条，不自动循环增加轮数。
- 图生图首轮最多 2 次真实请求：单图与多图各一次；能从同一次请求证据覆盖的不要重复收费。文本功能验证也优先静态与已有结果，必要的实际请求记录数量及用途。更多收费、特意复现重复扣费或大规模压测必须先向用户说明并取得新增预算。
- 10～20 次受理/去重/查询验证不等于 10～20 次付费上游生成。使用正式调度暂停能力保持新任务 queued，验证后取消这些任务，再只放行批准的真实任务。
- 单个管理员账号，不做注册、多用户、计费、Redis 集群和新框架。
- 自动清理五项独立开关：生成文本/图片/视频/缓存天数预填 2，原始资料预填 30；全都默认关闭，天数可填正整数。用户开启原始资料清理后须真实按规则清理，不一概跳过。
- 先保护任务输入、文件归属和并发版本，再做删除；禁止扫整个工作区按扩展名或 mtime 粗暴清理。
- 用户缩小验收规模并非取消登录、任务恢复、清理安全等承诺；4～7 个工作日是历史规划估算，不是免验收期限。

检查项：

- 核对本地依赖和 Bun 版本。桌面构建清单为 Bun 1.4.0，Docker 当前 1.3.14；选定能通过实际功能验证的 Linux 版本，记录理由，不无证据全量升级依赖。

- 只读登录服务器复核系统、资源、端口和现有容器身份，记录基线；此前 4 核/8GB、可用内存约 3.6GB 是历史快照。不得停止其他应用或执行 prune/down -v。

冻结下列契约后再发并行实现任务。命名可在本阶段按实际类型调整一次，此后由主控管理版本，不能各自猜测。

### 4.1 任务接口契约

| 操作 | HTTP 路径建议 | 核心语义 |
| --- | --- | --- |
| 提交 | `POST /api/ai/media/tasks/submit` | directory、稳定 batchKey、items；每项 itemKey、媒体请求、可选 canvasId/nodeId。逐项返回 accepted/existing/rejected 及 taskId |
| 查询 | `GET /api/ai/media/tasks/get` | 经授权 directory + taskIds，或 batchKey/batchId + cursor；有限页大小，状态统计与 nextCursor |
| 取消 | `POST /api/ai/media/tasks/cancel` | 明确任务范围，持久化取消意图，区分上游是否确认取消 |

这些路径由对应路由文件自然生成。媒体请求复用现有 schema，不在各入口重造模型字段。HTTP 保持现有 `{code,data,message}` 响应，MCP 直接调用同一业务函数，不绕过鉴权伪造 localhost HTTP。

- 幂等范围：规范化工作区 + 客户端 batchKey + itemKey。客户端在首次发送前生成稳定 batchKey，即使首包响应丢失也能查回；服务端另返 batchId。重传同键同参数复用 taskId，同键不同参数冲突。
- 状态：`preparing/queued/submitting/running/downloading/succeeded/failed/cancelled/unknown`。输入快照未准备好的任务只能 preparing，不能调度上游；受理记录本身须先持久化。参考文件版本不符明确失败，不悄悄使用新内容。
- 每条结果字段：taskId、batchId、itemKey、state、createdAt/updatedAt、completedAt、输出相对路径、错误分类、cancellationRequested/upstreamCancellation；不要返回 Key、Base64 或敏感签名下载地址。
- 已受理和整批请求响应分开：请求中断后已持久化项仍存在，未受理项可同键重传；不能先反馈全部受理再后台发现没写记录。
- `succeeded` 仅表示有效结果已落盘；画布回写独立标识，回写失败不推翻成片成功。
- 旧同步工具如果保留须明确标注等待成片行为；新批量工具和视频节点必须走任务接口。禁止悄悄改变旧工具返回结构使已有调用方失配。
- 查询/调度暂停是正式运维能力，用受保护的服务器配置实现，不新增仅供测试的假队列入口。隔离环境首次运行暂停调度，用于非付费验收和迁移维护；正式启用前取消所有验证待处理项并核对清单。

### 4.2 供应商分阶段契约

在现有 `packages/providers/types.d.ts` 扩展可选异步提交/查询/取消能力（实际 lowerCamelCase 方法名冻结在契约文档），不强迫所有供应商一次重写。

- Dola：提交返回上游 ID；查询返回运行/成功/失败及结果定位信息；下载交公共受限逻辑。上游 ID 立即交宿主持久化，去掉硬编码 8790 台账。
- XMX：保留已修复参考图协议。同步生成结果可运行在后台任务中，但没有上游 ID 或幂等能力时不能承诺崩溃后安全自动重提，标 unknown。
- 不把密钥固化在任务记录，每次运行取已授权配置；记录适配器版本以便恢复。替换配置不能把旧任务拿到不相关供应商继续查询。

### 4.3 文件与清理契约

- 使用统一业务记录追踪 sourceKind（generated/original/cache/unknown）、mediaType、path、版本、createdAt/updatedAt/completedAt、cleanedAt 和活跃占用，不依据扩展名推断来源。
- 原始资料上传/导入、生成落盘、文本修改、改名/复制、删除都需同步归属；只有产品管理路径记录，不扫描任意服务器目录。
- 活跃任务输入快照、正在下载/保存/编辑的文件有占用保护；真正删除前在同一协调边界内重查版本和占用。清理器不用独立锁体系。
- 同一物理文件多归属需满足全部保留条件；来源不明和历史无可信时间的文件默认不自动清理。
- 新记录目录/文件用小驼峰，如数据目录下 `mediaTasks/`、`fileRecords/`，不要用短横线或下划线新建命名。只为确实复用提取模块。

## 6. G1 工作包的可执行清单

### P：供应商迁移与结果正确性

1. 只读复制有效源码逻辑至新包文件，保留 provider ID、模型名和 XMX edits multipart；备份文件不进入发布产物。
2. 下载 URL 校验来源与重定向，跨来源不携带供应商 Authorization。Key 只从配置注入，日志去敏。
3. 去掉 Dola 固定 8790 台账，提交/查询分开，保留上游 ID 与失败分类；明确不支持取消的返回。
4. 统一受限流式下载，边读边限额；真实媒体签名/可读性检查。上游成功但下载失败保留恢复依据，不重新生成。
5. 多输出逐项保存，某个失败不删除已有成功成果；文件与目录锁冲突只补保存，不重跑上游。
6. 参数按实际模型校验：图片数量、首尾帧、视频参考图数量、比例/分辨率/时长；不静默丢图或退化模式。
7. 交付：差异、协议说明、静态检查和无付费接口验证记录。真实生图/视频由 I 统一完成。

### Q：持久任务、恢复和受控并发

1. 提交前校验工作区/请求，先 durable 保存任务与幂等信息，再返回 accepted；索引可重建，避免关键双写不一致。
2. 固定输入快照；准备未完成不提交上游；批次支持分页和追加，不把验收数量写成上限。
3. 调度初始化建议生成并发 2、下载并发 2（可配置，后续实测）；暂停调度可查可取消，不丢已运行状态。队列容量按配置返回明确背压，不静默丢任务。
4. `submitting` 请求结果不确定时 unknown；有上游 ID 则恢复查询，绝不无条件重提。状态转换有版本/单任务串行保障，旧轮询不能把 cancelled/succeeded 覆盖回 running。
5. 429 按 Retry-After/退避；连接错误区分提交与查询/下载阶段。只对可安全重试阶段自动重试。
6. 取消、关闭观察连接、关网页语义分开；API/Key 不写任务文件；结果相对路径和归属正确。
7. 输出独立业务调用，供 HTTP/MCP/节点共享。同步旧工具明确保留或提供兼容迁移，不改变所有工具的返回值。
8. I 配合接入 SIGTERM：停止受理、提交关键记录、取消本机观察/子进程并留下恢复依据；不等所有长视频完成。

### A：账号、会话与设置安全

1. 保持完整 settings 保存，加 revision/expectedRevision。旧窗口冲突保留本地修改，不覆盖较新 Key/清理策略；服务端自动更新模型列表也产生新版本。
2. 单账号哈希，凭据从私有文件初始化，随机会话 Cookie，登录失败限速。认证不进入普通 settings。
3. 登录界面先于完整 settings 加载；未登录访问不出现无法挂载应用的死循环。正常登录后再 Pinia/业务初始化。
4. 401 对 Axios 和直接 fetch 一致处理，保留未保存内容；登录后查任务状态，不自动重放生成/删除。
5. HTTP 默认保护业务接口；MCP 使用独立 Token；A2A 保持认证或明确关闭未使用入口。不能把 settings/get 临时公开来绕过初始化。
6. 远程管理员权限与服务器工作区限制分开；同源/CSRF、Cookie 和代理信任范围正确配置，插件调试只允许管理员。
7. 验收：未登录敏感请求拒绝、正确/错误 Token 区分、登录/退出/过期、两个窗口设置冲突。隔离 HTTP 隧道可用开发 Cookie 配置，公网 HTTPS 必须 Secure，不能为方便测试长期关闭。

## 7. G2 工作包的可执行清单

### F：视频节点、画布、MCP 与后台标签

1. 视频节点首次提交前持久保存 batchKey/itemKey 与节点绑定（轻量待提交标识，不依赖全图保存）；标识无法保存时不得发起提交。超时、首包响应丢失或刷新后按原键查询/同键重传，禁止自动生成新键再次提交。得到 taskId 后更新绑定，状态由服务端权威记录提供；节点卸载仅停止观察，不取消业务任务。前台恢复立即查询，后台计时变慢不影响后台生成。
2. MCP 新增 `submitVideoTasks/getVideoTasks/cancelVideoTasks`（命名最终冻结），复用 Q 服务与现有工作区授权；查询有限分页，短响应，不经画布转发生成过程。
3. `node:generateVideo` 快速返回 accepted/taskId；只读 status/config 不触发全图 flush。未知第三方工具默认变更，不按名称猜测只读。
4. 画布变更保持串行；有界等待和排队取消独立，保留实际执行超时，不简单删除全部 120 秒保护。
5. 命令携带预期 canvasId/代际，网页执行前重查；旧连接迟到结果不能完成新命令。同项目切画布不误写。
6. 任务受理与随后保存失败分别反馈；画布采用版本保存，冲突保留本地内容。删除节点不重建，切项目不回写错误项目。
7. 长文本 length 显式标截断，保留部分文字；不要自动继续收费生成。
8. 媒体预览使用受保护同源 Range/metadata 和生命周期回收，不因离屏卸载取消任务。保持图片/音频旧行为兼容。
9. 在真实网页验证当前标签、切到其他标签、恢复前台、刷新/重开和重连。不得用 HTTP 调用冒充浏览器后台标签验收。

### C：来源与自动清理

1. 面板五类独立开关和数字天数，默认 off；结果/缓存 2，原始资料 30。留空、0、负数、非整数拒绝。
2. 首次开启或缩短时间提供候选预览后确认保存；定时执行不逐项问用户。正式数据保持 off，用户后续自行启用。
3. 结果从完成保存起算，原始资料从导入服务器起算，修改后重计；活跃占用解除再按规则延后，普通预览不永久续期。
4. 清理对象来自可信归属记录；原始资料 off 时保留，on 且满足期限与占用条件才删除。未知文件/历史无来源不自动纳入。
5. 任务恢复输入、幂等记录、插件备份不是缓存；浏览器 Blob 不通过服务器按天清理。
6. 删除与任务/文件操作共用协调，先标可恢复的清理意图、核对版本与引用，再删除并提交状态；崩溃后可重入。清理器单实例分批，不阻塞正常生成。
7. 节点显示已清理，不让旧页面重写旧结果，不删除整个项目或画布；共享文件按全部保留条件判断。
8. 验收不等待 2/30 天：只在临时 data 中使用产品正常生成/导入的数据，对其归属记录时间做明确登记的人工回拨，关闭服务后改记录、重启检查；不改系统时钟、不加测试接口、不创建测试代码。若此方法与实现持久格式冲突，改用可审查的等效人工验证并说明局限，不假报通过。

### D：Linux 镜像与独立部署

1. 优先复用现有 Docker/Compose，单实例、非 root 容器、持久卷。选定 Bun 版本后显式安装依赖并构建，保持命令独立。
2. 固定发布标识和产物哈希；自定义供应商随产物交付，内置节点/工具按版本同步且保留用户修改。不要靠清空 data 强迫升级。
3. 建议专属部署目录 `/opt/toonflow`，项目标识 `toonflow`，回环 `127.0.0.1:3930` 映射容器 3000；先确认路径与名称未被使用，已存在先核对归属，不覆盖。项目根目录不能占用已有应用数据。
4. 若 3930 被占用，选择另一个核实空闲回环端口并记录。不得为了释放端口停止其他服务。
5. 配置与密钥在运行时注入/受保护文件导入，不 COPY 到镜像。备份覆盖工作区、任务、配置和归属，写入镜像或同一被替换目录不算备份。
6. 域名缺失时通过 SSH 隧道在本机浏览器验收；不得向公网裸露业务端口。域名明确后只新增专属 Nginx 站点，nginx -t 成功再 reload，不 restart 整机或影响其他站点。
7. 健康/就绪与 SIGTERM 由 I 接入；部署前后核对其他容器身份和健康，保留证据。重启验证只操作本次 Toonflow 容器。
8. 更新前停止新受理、保留已知上游任务状态、一致性备份。回退校验数据格式，不能直接恢复旧幂等记录后重新收费提交，不删除数据卷。

## 9. 集成与验证命令

## 11. 进度门槛、止损与交付

完成条件：

- G0/G1/G2 产物完成并通过对应检查；核心 R 项要么修复并验证，要么有实证排除，不能只写“已优化”。
- V01—V12 逐项给出通过/失败/未覆盖和原因；核心鉴权、任务受理/恢复、参考图、清理不误删、可播放成片不能靠构建通过替代。
- 交付包含实际镜像 ID、发布标识、访问方式、MCP endpoint、设置/数据目录、默认清理 off、备份/回退步骤、剩余问题。
- 私有登录资料在外部交接文件，最终回答只给位置，不明文输出。
- 域名缺失时可交付“隔离回环部署已完成”，但不能把“公网正式上线”标完成。继续做所有不依赖域名的工作，只将公网阶段列为外部输入缺口；Goal 状态遵守工具规则，不凭空宣称整个目标实现。

止损：发现越权、密钥输出、越界删除、误删原始资料、未知任务被重复收费提交、受理记录丢失或其他业务受影响，立即停止本次相关危险动作，关闭新增调度/清理或回退本次专属变更，保留证据并修复。不得清理现场、删除卷、重发 unknown 或改其他业务掩盖问题。

已授权范围内自主继续实现和必要验证，不为每个可逆步骤反复求确认。只有域名等必需信息缺失、要超出收费样本、必须影响其他现有服务或改变明确需求时，提出具体问题并继续独立工作。
