# Toonflow 单人服务器二改与上线方案

编制日期：2026-10-08（Asia/Shanghai）。本文件是待实施方案，不代表代码已经修复或服务器已上线。

执行入口已整理为同目录 `deepseekExecutionPlan.md`，启动提示词为 `deepseekStartPrompt.md`。开工以执行任务书的最新范围为准：画布继续依赖打开的网页，不实现无网页画布；10～20 次非付费受理验证，首轮真实视频总计最多 2 条，不做 100 条真实生成。真实连接资料在仓库外私有交接文件，见执行任务书第 2 节。

## 1. 目标与边界

- 将现有桌面版的实际可用配置、已修复图生图适配器和视频能力迁移到 Linux + Docker。
- 一个管理员账号登录网页，外部 Agent 通过独立 MCP Token 使用；不增加注册、多用户、计费或复杂权限系统。
- 面向短剧工作流完成后集中提交的大批量视频任务，当前单条视频最长约 30 秒。100 条只是常见规模示例和基础验收样本，绝不是批次或项目上限；支持超过 100 条并持续追加任务。受理、执行、下载、保存分别有可查询结果。
- 批次总任务数、单次传输条数、持久队列容量和实际执行并发分别设计；不把 100 写成任何固定业务上限。传输分批使用同一批次编号及稳定单项标识，支持中断续传和去重。
- 页面关闭、MCP 断连不能丢失已受理视频任务；支持具备查询能力的上游任务恢复。
- 保护现有桌面安装、API Key、项目文件和服务器其他应用。
- 不新增任何测试文件、测试框架或自动检查入口。按阶段单独执行类型检查、构建、实际 HTTP/MCP 和浏览器验证。

本轮只做只读核查和方案文档。没有修改桌面版、业务源码或服务器服务，没有调用收费生成。

### 对 120 秒问题的准确归因边界

实际安装视频节点已经立即返回 `status: generating`；实际 stdio 转发超时是 30 分钟；自定义 dolaVideo 的等待上限已改到 12 小时。因此不能再把原因写成“节点没有快速返回”或“stdio 只有 120 秒”。

确实存在的是页面控制的多层 120 秒限制与忙时拒绝。还需要实际失败调用的工具名称、客户端错误、并发方式和时间才能最终归因；当前 app.log 没有对应超时报错。无论具体触发点在哪，服务端持久任务仍是可靠批量运行所需能力。

## 4. 选定方案

方案 A：仅增加代理密码、延长超时。改动少，但无法解决页面关闭、任务恢复、并发拒绝、重复提交与落盘失败，不满足目标。

方案 B：单账号应用登录 + 单实例持久任务调度 + Docker + 现有 Nginx。推荐。复用现有 Express、Bun、供应商和工作区文件能力，不增加 Redis 或多进程集群。

方案 C：独立消息队列、多个 worker、数据库和多实例。当前没有必要；如未来单实例确实达到容量上限，再以实测结果决定扩展。

## 6. 短剧批量视频任务的最小可靠设计

### 受理与查询

- 复用现有请求 schema 和公共媒体适配逻辑，新增独立的提交、查询、取消路由文件及对应 MCP 工具。
- 一次批量提交携带客户端幂等标识；先做请求大小限制、工作区授权和基础校验，再持久化任务并返回 `batchId`、每条 `taskId` 及受理/拒绝原因。
- 相同幂等标识和相同内容返回原任务；相同标识不同内容报冲突。映射须持久保存，并声明有效保留期。
- 批次视图按 queued、submitting、running、downloading、succeeded、failed、cancelled、unknown 分组。受理成功不显示为生成成功。
- 排队不通过一个等待成片的 HTTP/MCP 请求实现。Agent 通过短查询获取进度；网页刷新后重新订阅或查询。

### 调度与容量

- 单 server 进程执行队列，按供应商配置并发和速率；初始建议生成并发 2、下载并发 2，作为待验证保守值，不承诺未经验证的吞吐。
- 按磁盘和内存预算配置队列容量、单次请求大小及参考媒体总字节预算，不将批次锁死为 100 条。大批次按传输容量分批持久受理，返回准确的已受理/未受理明细，容量不足时明确反馈并允许后续续交，不静默丢弃。排队时不把所有媒体读取到内存。
- 入队和查询需保持短响应；100 条基础受理目标在正常条件下 10 秒内，不等待上传参考图到上游或生成完成。大文件输入快照另行显示准备状态，不用假受理掩盖未持久化。
- 上游 429 按 Retry-After/退避调度；不得因一次 429 重发整批。明确区分安全的查询/下载重试和可能重复付费的提交重试。
- 运行队列上限和每供应商并发分别控制，防止一个模型长时间占满全部调度能力。

### 持久化与恢复

- 使用现有 `@toonflow/file`，任务快照显式 `writeAtomic`；单进程内按任务协调更新，不引入第二套底层文件工具。
- 持久记录任务 ID、批次、请求指纹、固定工作区、输入快照、provider/model、上游任务 ID、状态时间、输出结果及去敏错误。
- 供应商适配需暴露提交与查询阶段，接到上游任务 ID 后立即保存。不能继续把任务 ID 封闭在持续 12 小时的函数局部变量里。
- 重启后 queued 继续执行；有上游 ID 的任务恢复查询；下载未完成的任务继续下载或重新查询结果地址。
- 已发出提交但没有拿到上游 ID 的标记 unknown，利用上游幂等/查询能力核对；没有此能力时需要人工确认，不承诺跨网络故障绝对 exactly-once。
- 确认文件完整读取并原子落盘后才标记 succeeded。结果地址过期时优先查询上游刷新，不重新付费生成。
- 取消排队任务阻止提交；运行任务仅在上游支持时确认上游取消。停止本地跟踪不等于停止扣费。

### 保存与画布回写

- 结果落盘使用短等待队列或任务独立目录解决争锁，继续遵守工作区边界及独占新建。保存失败只重试保存，不重新生视频。
- 多结果逐个记录状态，保留已经成功落盘的文件，避免后一个下载失败删除前面的成果。
- 画布保存 taskId 与预期目标，页面重开按任务恢复状态。项目切换、节点删除或用户修改后，不得将旧结果写错地方；结果仍可通过任务记录找到。
- 不要求浏览器常开，也不自动替用户重新创建已删除节点。

## 7. 登录、安全与远程兼容

- Bun/Express 实现单管理员账号，密码使用密码哈希函数；认证配置与普通 settings 分离。
- 最小界面仅账号、密码、登录及必要错误提示；退出和会话过期行为明确。
- 随机会话 ID，HttpOnly、Secure、SameSite Cookie；服务端单实例内存会话可接受重启后重新登录。设置登录失败限速。
- `/api` 默认认证，登录及必要公开状态使用明确白名单；尽量在大请求体解析前拒绝未认证请求。
- `/mcp` 使用独立 Bearer Token；`/a2a` 保持自己的认证或关闭未使用入口，不允许通过例外入口绕过鉴权。
- 同源部署收紧 CORS，写操作检查 Origin/CSRF；代理信任范围固定，不能把伪造 localhost 请求头当作管理员身份。
- 管理员授权与本地目录授权分离：远程管理员可管理可信插件和设置，工作区仍限制在服务器专属目录。
- 工作区文件增加适合媒体/文档使用的隔离头；HTML/SVG 不能作为登录域下不受控活动文档执行。
- 供应商调试和代码安装只给管理员；VM 不宣传为安全沙箱。单人可信代码场景不额外构建复杂沙箱系统。
- NDJSON/SSE 增加兼容心跳，前端处理器同步适配；Nginx 禁缓冲并配置合理读超时。任务生存周期独立于观察连接。

## 8. 数据安全与大规模视频画布

- 画布保存复用 `readTextSnapshot/writeTextSnapshot` 和服务端 `expectedRevision`。过期快照返回 409，保留本地修改并提供重载或另存，不直接覆盖。
- 视频优先使用同源、带会话 Cookie 的文件 URL，利用现有 Range 能力；默认只取 metadata/缩略图，播放时再加载，避免预先整段下载 100 个视频。
- 离屏/不活跃播放器可释放媒体缓存，但不能因此卸载服务端任务或丢失节点状态。
- 当前媒体文件 100MB 限制应根据实际视频大小确认。调整时同步代理、服务端、磁盘与资源预算，不改成无限制。
- 项目列表经 `main.ts:41` 注册的 `settingsStorage` 存入服务端 `settings.stores`；localStorage 只是旧数据迁移来源。此前“仅在浏览器保存”的判断已纠正。迁移需核对其中的 Windows 路径；跨窗口配置保存冲突见 R22，不需要另外重做一套项目列表持久化。
- 自定义节点/供应商保护：内置产物按版本同步，用户修改不得被升级静默覆盖。记录来源、哈希和升级备份，避免新镜像仍加载旧插件。

## 9. 部署、迁移与回退

1. 保存桌面有效文件、源码和配置备份清单，确认实际项目位置及要迁移的范围；不移动或删除桌面原件。
2. 在隔离环境构建 Linux 镜像，验证选定 Bun 版本、供应商 multipart、媒体能力及 FFmpeg；不在繁忙服务器上无约束构建。
3. 使用独立 Compose 项目、专属数据卷、非 root 容器用户。宿主端口建议回环 3930 映射容器 3000，实际部署前复核占用。
4. 复用宿主 Nginx 为专属域名增加独立站点，配置 HTTPS；不重用其他应用路由或修改其他业务容器。
5. `/app/data` 持久保存配置、可信插件、工作区和任务状态。备份不只备份配置文件，还包含素材、画布、任务及恢复所需输入。
6. Windows 绝对目录改为服务器工作区映射；检查中文文件名、路径分隔符、大小写、相对资源引用和会话路径，不能对 JSON 全局盲替换。
7. 先用临时数据完成验收，再迁移正式配置和项目。API Key 不通过页面报告或日志泄漏；桌面 MCP 凭证不自动延用。
8. 固定发布镜像版本、产物哈希、任务数据格式版本。升级前停止新受理并检查任务状态、生成一致性备份；不要只备份正在变化的一半文件。
9. 回退前确认旧程序可读当前任务格式；不兼容时先停受理并按备份方案恢复，防止恢复旧幂等记录后重复提交上游。不得直接删除数据卷回退。

## 13. 设置面板：自动清理（新增需求设计）

用户最新要求：生成结果、原始资料、缓存均提供独立自动清理选项；原始资料保留天数预填 30 天，可手动修改。100 条不是任务上限。以下为设计，尚未启用或执行任何删除。

### 面板结构与默认值

在现有设置侧栏新增“存储与清理”，沿用现有设置保存方式，不另建管理页面。

| 项目 | 控件 | 初始状态 |
| --- | --- | --- |
| 生成文本 | 独立开关 + 保留天数数字输入 | 关闭，天数预填 2 |
| 生成图片 | 独立开关 + 保留天数数字输入 | 关闭，天数预填 2 |
| 生成视频 | 独立开关 + 保留天数数字输入 | 关闭，天数预填 2 |
| 原始资料 | 独立开关 + 保留天数数字输入 | 关闭，天数预填 30 |
| 可再生成缓存 | 独立开关 + 保留天数数字输入 | 关闭，天数预填 2 |

天数为正整数，允许直接填 2、3、7 等值；关闭表示不自动清理。开启但留空、填 0、负数或非整数时不可保存；不能把空值解释成立即删除。后端校验与前端一致。

面板仅补充必要信息：清理范围、最近清理时间/释放空间/失败数量，以及“预览待清理”入口。首次开启或缩短期限时展示当前预计受影响文件数与体积，保存生效后后台按规则运行，不要求每次清理都确认。不新增回收站、批量下载或复杂文件管理功能。

### 两天的含义

- 表示保留至少 48 小时，不是“每两天把所有内容清空”。
- 生成结果以成功保存时间起算；被用户修改后从最后一次修改重新计时。
- 原始资料以成功导入服务器的时间起算，用户修改后重新计时；预填 30 天表示至少保留 720 小时。源文件自身旧修改日期不能导致刚上传就过期。
- 正在排队或运行的任务所需素材不清理；任务占用解除后再保留所设天数，避免刚完成下游生成就立即删除依赖。
- 缓存以最后实际使用时间计算，不依赖操作系统不可靠的 atime。
- 服务端每小时小批检查一次；过期后在下一次扫描删除，因此时间是“满两天后逐步清理”，不是精确到秒。
- 重启后恢复检查，按批处理积压，不能一次扫删大量文件阻塞正常工作。单进程只运行一个清理调度器。

### 清理对象与保护规则

- 按明确来源与归属分别处理生成结果和原始资料，不按扩展名扫整个工作区。原始资料开关仅控制用户导入到服务器的小说、剧本、分镜、参考图和原视频等文件；关闭时始终保留。项目画布结构、配置、API Key、插件和会话记录不在这些清理选项范围内。
- 生成文本与用户粘贴/编辑文本可能都保存在 `assets/<nodeId>/content.md`；当前文件位置不足以区分来源。新增明确来源标记，来源混合或不明的文本默认保护，不直接删除整个文本节点目录。
- 既有历史文件没有可靠来源/时间记录时默认保留，不因启用清理就给旧文件追溯定龄批量删除；后续可在明确确认归属后纳入。
- 正在生成、提交、轮询、转码、写入、下载到浏览器、编辑或被排队任务引用的文件暂缓清理。检查后删除前必须再次校验归属、版本和占用状态，并与任务/工作区操作共用锁，避免检查与删除间发生竞争。
- 被多个类别共同使用的文件，必须满足所有归属类别的清理条件才可物理删除；其中任一类别关闭清理、未到期或仍被活跃任务占用，均保留。不能因生成结果到期而提前删除同一个原始文件。
- 仅被普通画布节点静态引用不意味着永久保留；到期后保留节点与连线，分别显示“结果已按保留规则清理”或“原始资料已按保留规则清理”。之后再次执行依赖它的工作流，应提示重新上传，不自动重新付费生成。首次开启原始资料清理时明确说明这一影响。
- 文本清理与画布状态变更必须有可重入的清理记录及版本校验。网页旧快照不能在清理后重新写回旧内容，也不能因为清理导致整个画布加载失败。
- 清理成功后记录清理时间，任务保留精简状态和必要的幂等记录；不要把任务恢复数据和防重复扣费记录当缓存删除。

### 缓存的实际范围

代码中的 cache 包含浏览器 Blob、内存 Map、模块缓存和若干操作临时目录，不存在一个可以放心整体清空的统一缓存文件夹。

- 天数规则只针对明确登记为可再生成的服务器磁盘缓存/临时中间文件；无符合项时显示 0，不制造无意义缓存目录。
- 活跃任务的参考快照、唯一成片、失败任务续下载依据、插件安装备份与回滚目录不算普通缓存。
- 浏览器 Blob/播放器缓冲采用页面和使用生命周期及时释放；服务器不能定时替用户删除浏览器或本机下载目录。
- 所有磁盘删除复用 `@toonflow/file` 与现有工作区路径校验，不跟随越界符号链接；失败逐项记录并下次重试，不能标成成功或触发重新生成。

### 下载与提示

用户习惯生成后立即下载，因此保留天数规则适用，但服务器不能证明浏览器已经完整保存到用户电脑。只按用户设定期限清理，不以“点击过下载”作为安全凭据。面板明确提示：“开启后，过期资料将从服务器永久删除，请在到期前下载。原始资料删除后，再次运行相关工作流需要重新上传。”仅作用于服务器受管文件，不删除用户电脑上的原始文件或下载副本；现有备份是否保留副本由独立备份策略决定。

### 验收补充

- 默认关闭时不删除任何文件；分别启用类别仅影响该类受管生成结果。
- 满 48 小时后才进入候选；修改、活跃任务引用和下载占用会正确延后。
- 原始资料关闭清理时不删除；开启后按自填天数计算，修改与任务占用正确延期。刚导入的旧文件不会因旧 mtime 提前删除。
- 来源不明文件、未满足全部清理条件的共享文件、配置、任务幂等记录和恢复输入不被误删。
- 删除与并发读写、排队转运行、进程重启的竞争不会导致任务丢失或画布损坏。
- 删除后节点显示已清理状态；不自动重生成、不重新写回过期结果。
- 缩短期限时预览准确；停用后不继续开始新的删除，已进入原子删除阶段的结果如实记录。
- 清理失败展示数量与原因，释放空间只统计实际删除结果；不同文件系统硬链接等情况不把逻辑文件大小当作精确磁盘释放量。

**R16—R17：控制命令准确、查询轻量。** 节点工具标明只读/变更属性，只读查询不执行全图 flush；真正变更保留必要保存。任务受理与画布保存结果分别报告，受理后出现保存错误仍能得到 taskId。控制消息携带预期 workspace、canvasId 与上下文代际，网页在实际执行前再次验证；显式切画布使用明确源与目标。验收覆盖大画布连续状态查询不产生全图保存、保存失败不丢受理事实，以及延迟命令期间 A→B 切换不会修改 B。

**R18—R19、R30：安全且受限的结果下载。** 解析下载 URL，仅对确实需要鉴权的同源或明确批准来源附加密钥，公开 CDN 不带供应商密钥；校验重定向去向，拒绝不支持协议及凭据 URL。不能把“任意同域名子路径”自动当可信业务下载。复用受限流式下载，预检 Content-Length 并逐块计数，超限或取消立即释放连接；参考输入与结果下载使用各自预算。对支持格式检查真实签名，拒绝 HTML/JSON 错误页；视频在受控资源下做可读性验证后才标成功。使用非付费可控响应验证跨来源无密钥、超大/无限分块响应停止读取、伪装 MIME 不成为成功视频；日志不得包含 token 或签名 URL。

**R20、R31：文本完整性和模型限制。** 普通文本与工具输出统一暴露截断状态，保留部分正文、明确提示未完成，不自动追加收费请求。用户显式设置的有效上下文/输出限制优先，静态表仅作缺省值。验证 length 与正常 stop 的状态差异，以及同名模型设置较小限额后列表和实际调用都采用设置值。

**R21、R23：资源调度覆盖所有重操作。** 视频提交、结果下载、模型请求、Agent 工具和 FFmpeg 分别配置执行并发，总任务数可持续排队，不限制成固定 100 条。不能在整个父 Agent 生命周期占住全部槽位再等待子 Agent，避免死锁；控制活跃模型/工具请求并允许父等待时让出资源。FFmpeg 限制同时运行数、合理线程/日志预算及可配置超时，取消能移除待执行项并等待子进程释放文件。运行程序版本检查按实际路径和更新状态做短期缓存、并发合并，安装或配置改变后失效。验收记录最大同时执行数、CPU/内存/子进程数量、多级委派可推进、取消后无遗留写入。源码未设应用层容量不代表已实测资源耗尽。

**R22：设置也需要版本冲突保护。** 保持现有完整覆盖语义，读取携带 revision，保存检查 expectedRevision；过期返回 409，保留未保存修改并要求用户处理冲突，不默默转为部分合并。服务端内部修改模型列表也须反映版本变化。短时间重复自动保存可在保持顺序和失败反馈的前提下合并，避免深监听每次变化都发送完整配置；清理开关/期限使用明确确认后的保存。两个窗口修改不同设置时，旧窗口不得撤销较新设置或恢复旧密钥。项目列表继续复用现有服务端存储，不新建第二份数据源。

**R24—R25、R29：按供应商能力正确组包。** 对照实际上游协议补齐 Wan 单首帧，审核结果必须完整并按原始素材标识还原顺序，不能缺图继续扣费生成。音频开关支持则正确传递，不支持则移除能力声明或明确拒绝。采用最终请求体/附件证据验证，而非只看界面选项；不能把内置供应商缺陷直接当成当前自定义 dolaVideo 故障。首期以实际使用两供应商为主，其他供应商若保留为可选能力，应在开放前修复或明确不可用模式。

**R26—R27：一致识别与有界会话。** Agent 与网页统一检查根级画布标记，快速路径不成立时在明确大小预算内完整解析；覆盖标记后置、嵌套假标记与损坏文件。先验证 MCP SDK 会话生命周期，再补空闲 TTL/容量回收；不清理活动调用，业务任务不跟着会话过期删除。循环异常断连、重新 initialize 后检查会话数量可回收，不以业务批次上限代替会话保护。

**R28：明确持久化承诺。** 在统一 file 包为关键任务受理、幂等记录、上游 ID 提供显式 durable 写入选项：同步临时文件、原子替换并在 Linux 同步父目录后确认；不让所有画布自动保存都承担同样成本。状态与幂等键尽量在同一关键记录中原子提交，可重建索引，避免两份记录只成功一份。结合存储系统实际保证说明故障边界；普通进程 kill/restart 不能证明主机掉电持久性。

### 登录与上线步骤的补充约束

1. **登录启动顺序必须调整。** 当前 `apps/web/src/main.ts:40-45` 在挂载应用前读取完整设置；如果只保护 settings/get，未登录时会进入“启动失败”，连登录页也无法显示。先加载最小认证状态并挂载登录界面，认证成功后再加载业务设置/Pinia。不能为让登录页显示而把带密钥的设置接口公开。
2. **会话过期要有统一行为。** Axios 和直接 fetch 的 401 都进入登录恢复流程，保留尚未保存的本地编辑，不自动重发可能已受理的生成/删除请求；重新登录后按 taskId/幂等键查询。
3. **健康检查与优雅停机列入部署实现。** 当前 Compose 仅有重启策略，独立入口未实现业务级停止受理与排空。新增最小存活/就绪检查，容器可启动不等于任务恢复和数据目录可写已就绪。SIGTERM 时先停止受理，完成关键状态保存、协调清理器与写入，再在宽限期内退出；长上游任务留恢复依据，不要求部署必须等全部视频生成完。
4. **路由生成保持显式步骤。** 现有生产构建不自动执行 routes。新增认证/任务/清理接口后按仓库要求先运行 `bun run routes`，核对实际注册结果，再 typecheck/build；不把这些步骤偷偷绑定进其他命令。
5. **不改变无关服务与框架。** 不把独立 updateServer、桌面启动器或所有插件重新设计当作服务器上线必经条件，也不增加 Redis、多用户、注册和计费功能。
