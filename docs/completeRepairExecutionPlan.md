## 5. 开工时冻结的数据与操作契约

### 5.1 状态、时间和容量

保留 preparing / queued / submitting / running / downloading / succeeded / failed / cancelled / unknown 及 trackingStatus=active/paused/blocked。状态表示已知业务事实；trackingStatus 表示是否继续跟进。unknown 不作为可丢弃终态。

一次上游提交 90 秒；查询 30 秒；下载连续无数据 60 秒、单次尝试 15 分钟。媒体大小等已有安全限制不放宽。供应商加载、快照读取、输入校验在提交网络计时之外；定时器从真正开始网络尝试计时。

确定未发上游的准备失败可记录为“提交前失败”，不占保守在途额度；进入提交尝试后无法证明未受理才转 unknown。进入可能发送的临界点前持久记录提交尝试事实，不能只依赖内存标志。提交返回结构不含有效 ID，也不能简单认为上游未受理。

| 事实 | 生成额度 | 后续动作 |
| --- | --- | --- |
| preparing/queued，尚未提交 | 不占；派发前申请 | 等待可用额度 |
| submitting/running，上游未终结 | 占 | 查询原任务 |
| 无 ID unknown，尚未知情放弃 | 保守占 | 按键找回或核对 ID，不重提 |
| 上游未终结且 paused/blocked | 仍占 | 恢复后续查 |
| 上游明确成功，downloading 或下载 paused/blocked | 不占 | 独立下载并发，数据仍受保护 |
| 明确上游失败/取消、可靠完成 | 不占 | 保存结果和历史 |
| 用户明确放弃核对 | 解除保守额度 | 保留历史、输入和重新核对入口 |

重启先装载旧任务、恢复保护及在途统计，再放新 queued。历史在途超过配置时，只禁止新提交，旧任务查询仍运行。未来 retryAt 不得被重启、pause/resume 或手动刷新清零。下一次尝试不早于上游 Retry-After 与本地退避的较晚值，抖动也不能突破下限。

查询断网、超时、429、5xx 保留业务状态并退避；认证、账户或协议不兼容保持 blocked；上游明确业务失败才属于上游生成 failed。下载地址过期只用原 ID 补查；无法刷新时标明结果不可补取，不自动重新生成。

### 5.2 HTTP、MCP 与操作语义

保留现有正式入口：

| HTTP | 对应能力 |
| --- | --- |
| POST /api/ai/media/tasks/submit | submitVideoTasks；逐项 accepted / existing / rejected |
| GET /api/ai/media/tasks/get | getVideoTasks；按 taskIds、batchId 或原 batchKey 查询并分页 |
| POST /api/ai/media/tasks/pause | pauseVideoTasks |
| POST /api/ai/media/tasks/resume | resumeVideoTasks；可携 bindTasks |
| POST /api/ai/media/tasks/cancel | cancelVideoTasks |

HTTP 与 MCP 共用业务函数及校验，保持现有 {code,data,message} HTTP 外壳。需要拒绝时设置真实 HTTP 状态，逐项批次结果保留 itemKey/taskId 与原因。HTTP、MCP schema、类型和描述同轮更新，不能仅改服务端实现。

1. accepted 与 existing 必须指向已持久化记录；不能返回随后被首写失败回滚掉的 ID。同键同内容返回原 ID，同键异内容拒绝；部分已受理项在请求断开后仍能按原键找回。
2. 单任务 pause 对已有任务跟进和 unknown 生效，阻止后续查询/下载。正在 submitting 但无 ID 时先记暂停意图，不能为实现 pause 而强杀提交并丢掉可取得的 ID。
3. pause 必须约束迟到回调。迟到查询可以记下已取得的上游事实，但不能把 paused 改成 active、继续派下载。已经进入不可中断的可靠落盘段可以收尾，操作响应如实反映最新状态。
4. resume 只恢复原 ID 查询/下载，遵守 retryAt；拒绝无 ID queued/preparing。没有 ID 的 unknown 只有核对并成功 bind 后才能恢复。业务失败、上游取消等终态不借 resume 新生成。
5. 普通 cancel：确定未提交才可本地 cancelled；上游明确确认取消才可声明上游取消。取消请求发出或返回未知不等于已经取消。下载中的 cancel 表示暂停取回，保留 downloading 与恢复能力。
6. cancel 与成功相遇时保留成功事实及结果，不把旧取消响应覆盖到新完成状态。取消响应没有输出时，网页必须再读完整摘要。
7. 在现有 cancel 请求新增可选 abandonUnconfirmed，默认 false，仅适用于 unknown 且没有 upstreamId；其他状态逐项拒绝，不能把已知 running/downloading 改成 unknown。只有用户明确选择“放弃核对，知道上游可能仍在生成”时为 true；保存 abandonedAt，保留 unknown、原键、输入和历史，trackingStatus=paused，解除保守额度，不声称上游取消。重复同次放弃幂等；MCP 工具描述同样说明，普通取消不能默认传 true。
8. abandonedAt 表示历史，不能永久当作免计容量开关。放弃后核实原 ID 仍可 bind/resume；成功绑定/恢复时在同一持久化操作记录 abandonRevokedAt，撤销当前豁免并按实际未终结事实计入额度，保留放弃历史。有效豁免仅限无 ID unknown 且尚未撤销的放弃；恢复使在途超过配置时继续查询旧任务，只禁止新提交。放弃期间也继续保护输入、幂等键和恢复资料，不因容量释放顺带解除清理保护，更不自动创建新任务。
9. 返回摘要至少完整透出已有 trackingStatus、waitingReason、retryAt、resultReadyAt 及本轮实际采用的放弃字段。所有者在 v3 记录最终字段，不输出 Key、Base64 快照或签名下载地址。

### 5.3 持久化、恢复与停机

复用现有协调机制，按批次保护完整 JSON 快照：构造候选 → 原子持久化 → 发布公共内存视图。首写进行中可以有内部保留位/Promise，但读接口与幂等重传不能把它当已持久任务返回。失败向调用方传播，不能 warn 后成功。

stopping 同时拦住新受理、新作业、迟到 tick 及可能派工作的恢复操作。顺序为：封闭受理/派发 → 清启动与周期 timer、停止清理派发 → 关闭 MCP 派发并停止监听接收新请求 → 收敛普通 I/O → 等待在途受理、作业及关键落盘 → 最后排空全部写队列 → 关闭剩余连接并退出。HTTP、独立 MCP listener、清理和调度都纳入协调。

代码一旦已经拿到 upstreamId，保存该 ID 不再被普通 abort 分支跳过，并且合并最新暂停/取消意图。不能靠“多等十秒”替代这项修复。操作系统强制杀进程或掉电前尚未落盘的数据不承诺绝不丢失；没有可靠事实时按 unknown 恢复。

恢复必须汇总逐项错误。无法装载/确认任务台账、恢复保护或在途数量时 schedulerReady=false，停止新生成和清理并给出可诊断错误；不能 catch 后静默宣布 ready。明确识别、已可靠保存为 blocked 的业务任务可以完成装载，但健康摘要须列受阻数量及原因。

### 5.4 供应商身份与 bind

比较原 providerId/modelId、完整规范化 API 基址（协议、主机、端口、路径）、原 providerRevision、查询协议兼容及非敏感凭据身份引用。相同配置槽不证明相同账户；历史缺字段也不等于自动兼容。

正常自行提交与人工补绑区分处理：本服务在可靠保存的提交身份下取得原 ID，且当前身份/地址/协议未变化时，可依据这条可信提交链继续查询，不要求上游每次额外回显账户和模型。人工 bind、账户/地址/协议变更或历史上下文不足时，才需要补充归属核对；不能因为 Dola 查询不回显账户字段，把所有正常新任务都卡成 blocked。

本轮保留原 providerRevision，不抹掉历史提交身份。源码变更仅在核对查询协议后通过明确兼容规则放行；不接受“仍有 asyncMedia 方法所以兼容”。凭据只存配置引用/版本及可以核实的账户标识，不把原始 Key 放进任务。

bind 流程固定为：检查工作区和任务当前状态 → 使用已核实查询身份对候选 ID 做只读查询 → 核对响应 ID、类型、模型、可验证账户 → 检查相同供应商账户下未绑定别的本地任务 → 锁内重查 → 一次可靠写入。重复绑定同任务同 ID 幂等，不能覆盖为另一个 ID，核对失败不留下半绑定。

Dola 当前适配只透出状态与 assets，模型/账户是否存在于真实响应尚需核对。优先用已有 ID 的非创建查询确认并最小透传；无此信息则保持“归属不可确认/blocked”，不能编造验证通过，也不擅自发新生成探测。可完成其余修复后在唯一交付清单列此上游限制。

旧记录迁移只补可以从原记录、现有可信历史证明的事实；不能把当前 Key 或当前账户反填成当时的提交账户。旧误写 cancelled/failed 的记录不批量激活或重提，保留历史，能确认原 ID 时才走只读恢复。

### 5.5 网页提交、恢复关联和保存回执

继续使用现有 directory + canvasId + nodeId 绑定，保留 batchKey、itemKey、taskId、outputPath 等字段；不再新建一套任务存储。

| 控制请求处于什么阶段 | 取消/断开后的正确行为 |
| --- | --- |
| 尚未调用提交 POST | 信号阻止后续 POST；只撤销这次确实未发出的新绑定，既有绑定不动 |
| POST 已发出、没有可靠受理回包 | 保留原键，异步按键查回；不能声称未提交或再生成 |
| 已取得可靠 taskId | 服务器任务独立继续；停止的只是控制请求或页面观察 |

signal 从 MCP 调用贯穿节点、目录准备、hook 和提交 fetch；每次提交前 await 结束重查 signal 与最初目录/画布身份。启动门必须在第一个 await 前建立，避免两次调用都判断无绑定。同步/异步分流之前统一检查未解决绑定与待保存输出。

首包未知立即启动按原 batchKey/itemKey 的恢复查询，不仅显示“稍后确认”而实际不查。空结果、401、断网、重新挂载、切回前台都不触发 submit；attach 失败不永久缓存失败 Promise。登录恢复保留草稿，不强制刷新页面。

本轮新增 writeBackToken（或在 v3 登记一个语义相同的现有字段复用方案）：首次绑定某个 taskId 的某个输出身份/内容版本时生成，并持久留在恢复绑定和节点最小结果元数据中。同一任务同一输出的重复轮询、重挂载、登录恢复必须复用已有 token；只有新任务或真正新输出才新建，不能拿查询更新的 updatedAt 当输出版本。已确认保存的同一结果不能因下次查询又变成待保存或把画布重新弄脏。画布发送保存前固定不可变文本，且从同一份文本快照导出 nodeId/taskId/outputPath/writeBackToken 清单。保存成功事件携该清单和此次 revision；禁止收到响应后读取当前节点凑清单。

只有目录、画布、节点、任务、输出和 token 全匹配才清临时关联。即使两个任务复用同一路径，也不能混认回执。旧绑定缺 token 时保守保留，通过取回真实结果并正常保存后清理，不能被任意下一次 ACK 清掉。

failed 含部分输出时保留失败原因，合法部分输出仍走待回写；cancel 响应为 succeeded/unknown/failed 时先查完整摘要，不能直接 clear。确认 cancelled 且没有待回写结果才可清。已清理输出不能再当作可播放成片绑定。

### 5.6 页面查询、revision 和设置重载

页面共享一套任务订阅/调度，按规范 directory 分组、taskId 去重，每次最多 200 个并显式 limit=200；相同 batchKey 查回合并，按分页找到 itemKey。超过 200 分片，不变成新总量上限。固定轮询、MCP 状态读取和用户刷新复用已在途请求，晚返回的旧订阅不能污染切换后的画布。

前台可沿用约 3 秒轮询，出错逐步退避至 60 秒；hidden 页面可放缓至约 15 秒，visible/online/重新登录立即补查。浏览器本身可能限速，不能据此保证精确周期。无订阅清掉 timer/事件监听；401 一次进入登录恢复，不让每个节点重复弹错。服务器任务状态 GET 只读本地，不同步等待上游。

MCP 控制连接与页面轮询分开，不能因 hidden、requestAnimationFrame 或失焦停止执行。整体关闭连接必须先标 closing、停止受理与 dispatch，再取消执行中的调用、清 timer、settle 队列和断连接；所有关闭原因共用该顺序。保留当前有界 FIFO 和预算，不把它们解释为视频总量/时长限制。

画布清冲突提示不能清掉重载刚取得的 revision。内容与 revision 必须来自同一次成功读取；重载失败保留草稿、冲突和原版本。禁止为旧内容临时取最新 revision 背书。

设置重载使用现有 saveQueue：等待之前保存收口，成功取得并校验 settings + revision 后整体发布，再清冲突和恢复自动保存；失败保留草稿、旧 revision、横幅与可重试按钮。重载期间不让旧快照排队覆盖新读取结果；不创建第二套 Store。

### 5.7 文件、清理和输出可用性

复用 lockWorkspaceFiles 的同路径/祖孙路径互斥。固定顺序：已有任务锁（需要时）→ 一次取得全部相关工作区路径锁 → fileRecords 串行持久写。清理持路径锁时只读任务快照，不反向等待任务锁；归属写队列内部不再取路径锁/任务锁。不新建全局事务框架。

输出处理的协调范围覆盖：校验路径 → 持久保护必要引用/占用 → 核实或写入真实文件 → 持久登记来源、版本和任务引用 → 发布完成事实 → 释放。需要分阶段写任务与归属时，失败必须留下可恢复保护，不得用 warn 掩盖。恢复保护没有建立或归属存储不可用时暂停清理，避免重启后使用不完整索引删除文件。

已有同名输出复用必须核实普通文件、工作区边界、真实 SHA256，不只比长度。台账已有 SHA 仍需检查文件存在及内容。缺失/损坏仅补取原结果，不能新生成；如果是明确自动清理，禁止后台把它自动下载回来“修复”。

清理扫描与 preview 都只产生候选。取得路径锁后重新读取最新规则、全部归属、实际版本及任务/编辑占用，再决定删除。五类默认值不改变；音频等没有独立规则的生成类别不擅自塞进视频类删除。

1. 删除意图与 cleanedAt 分开。实际删除成功，或结合持久意图确认上次删除已发生，才记 cleanedAt。
2. 删除失败、文件仍在，下一轮重新检查最新天数与占用；旧意图不能绕过延长后的期限。
3. 无清理依据的外部缺失标 missing，不能伪装成 cleaned。任务历史 state 可保留 succeeded，输出另表达 available/cleaned/missing 及 cleanedAt。
4. 任务摘要、网页节点、生成文本/素材/文件视图实际消费清理结果。已清理停止旧播放/下载，显示已清理，不变成上游生成失败。
5. 编辑占用关联已认证页面会话、规范目录和路径，覆盖文档/图片编辑及待保存结果。复用现有工作区入口和连接机制；hidden 不立即解除保护，关闭编辑器/会话断开后的有限宽限再释放。
6. 编辑占用过期后，旧页面写入仍须通过 revision 和清理记录检查，不能静默复活已清理文件；保留草稿供用户明确另存。预览、播放、只读查看不无限续期。
7. 清理计时：生成结果取可靠落盘与最后实际保护解除时间的较晚者；原始资料按导入/修改；普通文本按生成/修改，仍取实际保护解除后的较晚起点。部分输出等到长任务解除保护后仍有完整保留期。
8. unknown、blocked、暂停跟进但未解决的任务、输入快照、待下载/待登记/待回写数据不按普通两天缓存删除。任务与幂等台账、画布结构、设置、插件不在清理范围。

目录改名匹配源目录本身及真正的后代，不把 a 与 ab 当同一树。改名保留归属 ID、来源、多归属和计时；复制产生新记录 ID、从复制完成起计时，源记录不动。复制不照搬原任务/编辑会话的活跃占用身份；新副本引用按实际使用登记，历史来源可保留。未知文件仍未知。

目录操作在源/目标锁内完成文件操作和归属落盘；活跃任务/编辑占用的树拒绝移动。涉及终态任务输出改名时，Q 提供任务协调外层，按固定 taskId 顺序先取得受影响任务锁，C 再一次取得源/目标路径锁；锁内重查引用集合，有新增引用/占用则释放后重算或返回 409。禁止 C 持路径锁后调用会重新获取任务锁的 Q 更新函数，归属写队列内也不能反向调任务更新。失败安全回滚；不能回滚时明确报错并保护涉及范围，不能吞账本错误成功返回。

真实改名/移动时，终态输出和页面文件变更传播要同步更新定位，不能只迁归属账本、留下旧下载路径。复制不改变原任务的输出路径，副本只建立自己的归属和后续实际引用。

### 5.8 同步能力、资源边界与插件升级

首次执行按供应商能力分流：submitMedia/queryMedia 成对才走持久异步，否则复用原 generate 方法后台执行，可靠受理后快速返回。恢复阶段才要求原 ID 的查询能力。同步进程中断且结果不明保留 unknown，不自动重做；旧同步工具返回结构保持兼容，明确适用范围。

视频节点的网页点击与节点 MCP generateVideo 统一复用公共 submit 及同一恢复绑定链，同步供应商也返回可靠 taskId 后结束受理；移除或收口 startSyncGeneration 的直接等待绕路，不再因缺 asyncMedia 拒绝其首次后台受理。同步能力只保证当前服务进程内执行，进程中断后可能 unknown，不能承诺按上游 ID 跨重启续查。独立的旧同步 HTTP/媒体工具保留原成片返回结构并标明限制，不能把它们与节点的后台入口混称。

所有模型不支持的非空参考类别及 mode 在受理前拒绝，包括 videos/audios 等不能消费的字段。复用已有模型元数据和校验；不以“字段存在于通用类型”推定供应商支持，不静默丢参考。XMX 已修好的逐图 multipart 路径保留。

内置子 Agent 父任务让出槽后，必须在返回工具结果、继续推理前重新通过同一队列取得槽。让出一次、重新获取一次、释放幂等；取消等待及时移除。验收看实际执行生命周期，不只看计数变量。

FFmpeg 限流收敛到宿主实际启动进程的共同边界，覆盖 HTTP、工具注入、供应商及 fluent 工厂。保留现有链式 API，不改第三方全局原型。一个进程只拿一次槽，移除外层重复拿槽，防止外层占满后等内层死锁；进程真实退出后释放。明确 ffprobe、截图、拼接子过程是否及如何计入，不能笼统写“全部受限”。

插件按文件核对当前哈希、上次官方基线哈希、新官方哈希：未改官方文件自动更新；已经等于新版本直接登记；当前不同或旧基线不可信则保留定制，把新官方产物放到非自动加载的待更新位置。记录具体待处理项，原子保存升级清单，不只换总 BUILD_ID。涉及关键修复的定制文件由主窗口读取差异并最小合并、保留原副本；存在无法安全消解的定制行为冲突才集中报告，不能把旧插件原样保留便宣布对应缺陷已修。

每项记录：版本/环境、前提、实际操作、期望、实际结果、证据路径及现场恢复。表中的“未动态验证”不是放弃修代码，也不是自动判定通过。

证据分四类：①真实 HTTP/MCP/浏览器/进程行为；②隔离数据或人工时间调整演练；③源码路径与调用链核对；④未覆盖/外部限制。构建通过另外记录，不能代替①。没有真实运行证据时，不得填写“运行通过”。

12 次 submit 的默认分配如下。使用有效的既有模型描述和隔离资料，batchKey 首次确定后稳定保存；一次 submit 中的多项不按多次请求计数。若 V03 另发 submit，总数控制在 20 内，并把追加请求纳入同一账本。

| 请求序号 | 内容 | 预期分类 |
| --- | --- | --- |
| 1 | 新 batch，3 个不同 itemKey | accepted |
| 2 | 完全重传 1 | existing，ID 不变 |
| 3、4 | 同时提交另一个新 batch 的相同 2 项 | 合计只有一组任务身份，响应 accepted/existing 按真实先后 |
| 5 | 给第 1 个 batch 追加 2 项 | 仅新增项 accepted |
| 6 | 同 batch、同 itemKey，变更生成参数 | rejected 冲突 |
| 7 | 一次携已有项与 1 个新项 | existing 与 accepted 分项返回 |
| 8 | 完全重传 7 | existing |
| 9 | 不支持的非空参考类别或 mode | rejected/校验 4xx，明确原因 |
| 10 | 越界目录或未授权工作区 | 4xx，无受理 |
| 11 | 缺失的本地参考输入 | 明确未提交错误，不制造可能已受理的 unknown |
| 12 | 第二个合法隔离工作区使用同 batchKey/itemKey | 工作区隔离，建立自己的身份，不串项目 |

完成 V02 后保持隔离和暂停，逐项取消本轮所有已受理 queued，核对 batchId/taskId、cancelled 数量及无残余可派发项。不得通过解除暂停验证“是否真的会开始生成”。

## 10. 自审和自行收口规则

1. 每组实现后先审自身所有相关调用方，再交另一组检查：W 审 Q 的受理/返回/恢复语义；Q 审 C 的引用与锁；C 审 W 的清理消费与待回写保护；I 审跨组和资源边界。
2. 发现真实失败先记录原始现象、定位根因、由文件所有者修复，再只复跑受影响验证及必要回归。不能把失败记录删掉、换一组数据让结果变绿。
3. 阶段性写入进度，不每完成一组就停下来问用户是否继续。子 AI 提交“完成”后主窗口仍要核对文件、实际调用链与证据。
4. 不确定实现细节时按“现有能力优先、最小改动、不丢数据、不新增收费、不静默忽略输入”裁决。需要改本任务书的产品语义或缩减范围，才集中说明。
5. 可无费用完成的验证失败不是外部限制；必须继续修。确实需要上游新收费或现有工具不支持的动态场景，在证据表标明原因及源码核对情况，然后继续其他工作。
6. 完成实现后对照第 12 节逐项扫一次，防止只修 R01—R11 漏掉 F11/F14/F15/F16/F18、批量查询、准备阶段、首包观察或就绪错误。
7. 不添加“下一步再接 UI”“等用户再确认再部署”等人为分期。满足发布条件便执行第 11 节；真实发布阻断必须说出具体未满足条件，而不是泛泛“建议谨慎”。

## 11. 发布、现场保护与回退

本节授权范围延续既有 Toonflow 服务器部署任务。执行窗口只更新 Toonflow；这份规划本身不代表已经发布，也不要求现在重启线上。

### 11.1 发布前必须满足

- 已知 R01—R11 及附加任务均完成对应源码修复，跨组接线完成；没有已知仍会丢 ID、误清绑定、误删资料或重复生成的开放分支。
- server 检查和完整正式构建通过；新增网页类型问题已解决。既有桌面开发依赖导致的 web 检查限制若仍存在，按 G2 单列，不隐去。
- 可以在现有限制下完成的 V 项已执行，真实失败已修复；受限的自然跨天/付费窄竞态等有准确说明，不伪造通过。
- 新旧记录兼容、插件升级保护及候选安装文件已核对；回退版本对新字段的理解能力已有结论。
- 有唯一候选版本、明确的目标 Compose 项目/服务及数据位置。候选隔离实例已经停止或确保不会操作正式数据，不存在双写进程。

如果上述条件未满足，继续修对应问题；如果真正依赖外部条件，则保留现网、提交具体发布阻断和已完成项，不能说“已全部上线”。

### 11.2 准备候选，先保护现网

1. 从当前真实文件制作候选源码清单和哈希，不使用历史基线覆盖用户改动。按既有 Linux Docker 构建链生成新镜像，标签与 TOONFLOW_BUILD_ID 对应且不复用旧标签冒充新版本。
2. 构建不挂正式 data、不启动调度。镜像/构建上下文排除 .env、deploymentSecrets、真实 data、用户工作区及无关交接资料；运行时再注入配置。
3. 更新前记录当前正式任务分布、原 ID、输入/输出和恢复状态。第一次切换时实际运行的是旧 -11，尚无本轮 stopping 机制；不能调用候选版才存在的入口来停止旧版。
4. 已有 running/downloading 任务不要求等数天全部成片后才升级，但必须有可靠的原 ID/输入/输出记录，并先确认候选能够按原记录恢复。已持久 unknown 保留原键、占用和恢复资料，不能回滚成 queued。
5. 第一次替换旧版：候选准备好后，先以 Toonflow 专属入口的短维护规则阻止新的 HTTP/MCP 写入和生成控制，保留源站回环的受保护管理查询；再用旧版现有设置持久保存 paused=true 停止新派发。检查已建立的 MCP 会话及队列，等待既有控制和 submitting 收口、核实可取得的 ID 已落盘后才停止旧进程。Nginx reload 不会自动结束所有既有长连接，不能据此声称所有入口已关；也不能直接用旧版有缺陷的整体取消来强行排空。维护规则仅针对 Toonflow，无法安全收口时保留现场并记录阻断。
6. 需要修改暂停等设置时，使用正式 settings 接口读取最新快照和 revision，按完整保存契约写回，保留其他字段，尤其 wb 和模型 Key；不整段导入历史 serverSettingsImport。
7. 正式全局 paused 只是调度配置，不等于拒绝 HTTP/MCP 新受理；两个门都要落实。候选首次仍以持久 paused=true、原清理开关启动，确认恢复及安装无误后才恢复开工前调度并解除维护。本轮统一 stopping 用于新版本之后的正常退出，不能倒推成旧版已有。

### 11.3 一致备份和切换

1. 先准备好候选镜像，再按第 11.2 节对应当前版本的办法进入短维护，停止新提交派发并收敛关键临界段。首次替换旧 -11 使用维护门加旧版 paused 与在途核实，后续才用新版统一 stopping。只停止确认过项目标签的 Toonflow 服务，不使用整栈模糊 down。
2. 停止写入后备份 Toonflow 权威 data、认证/设置、任务/幂等记录、归属、用户插件、工作区以及当前 compose/env 和镜像身份。备份放不被镜像替换的私有目录，例如 /opt/toonflow/backup/repairExecution20261008；权限按敏感数据管理，不上传到仓库或普通证据目录。
3. 先验证实际绝对路径、空间和备份可读取，再切换；不得用递归删除清空目标“保证干净”。保留上一个镜像及安装清单，不 prune。
4. 服务器 compose 校验使用 docker compose config -q，避免打印包含密码的展开配置；只更新对应 image/BUILD_ID 和本轮确需的生命周期配置，不重置整个 .env。

### 11.5 回退规则

1. 触发条件：候选无法正常启动、任务恢复错误、关键接口回归、安装定制被破坏，或验证发现仍可能丢数据/重复提交。先阻止新生成和清理，保留日志及最新权威台账。
2. 若旧镜像明确兼容新任务/归属/插件数据，用保留的旧镜像和对应配置回退应用；继续保留最新 data，不恢复旧 mediaTasks 快照。
3. 若旧版会忽略新保护字段、重放任务或覆盖定制插件，不自动运行它写新 data。保持服务维护状态和最新数据，优先向前修复；如确需人工决定，在唯一阻断说明中指出具体不兼容处。
4. 绝不能通过恢复旧幂等记录、删除 unknown、修改为 queued、清初始化标记或清工作区强迫恢复。旧备份用于恢复真正损坏的数据，恢复范围需能证明不会丢掉发布后新事实。
5. 回退后重新核对原 ID、配置、插件和端口；记录实际回退身份与原因。失败部署不能继续在当前交付首页写“已上线新版本”。

### 13.3 何时可以结束，何时必须继续

**工程执行完成**：本文件所有代码工作包已完成并交叉复查；适用检查和可行非收费验证完成；没有已知未修核心缺陷；发布与发布后核对完成；文档、原始证据、受限项和回退说明齐全。自然跨几天等待、未发生的真实限流/丢包等在本轮没有运行证据，不妨碍如实交付工程结果，但不得扩称“所有长期场景已实测通过”。独立验收仍由审计窗口另行进行。

**尚未完成**：仍存在已知缺陷、假成功路径、只留接口没接消费者、可无费用验证却没做或失败、安装仍使用旧错误插件、发布没有完成。继续在授权范围内处理，不以“多数通过”“已经花很久”或上下文将满为由结束 Goal。

**外部阻断**：全部不依赖事项已完成，但凭据不可用、某个实际原任务的恢复归属无法证明、关键定制无法安全合并或现网任务无法安全收敛等确实阻断某项。没有实际受影响任务时，安全拒绝无法证明的人工补绑是已说明的能力限制，不因此阻止正常 Dola 提交链的发布；不能为了报完成取消该校验。一次列清具体事项、当前可用范围、已完成工作和需要的最少信息，不声称整体验收通过；Goal 状态严格按执行环境工具规则处理，不自行提前标 complete。

中途上下文不足时，把当前所有权、进行中的任务/进程、最后有效证据、下一步及禁止项写回 executionProgress，再继续衔接；不丢掉原目标，不重新初始化或重复收费。没有后台自动执行能力时也不能承诺稍后会自行完成。
