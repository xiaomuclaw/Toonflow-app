## 6. 工作包的完成条件

### Q：任务不会因为本地等待而失联

- 提交、查询、下载各自有限网络时限；异步 Dola 不加总寿命失败墙。有 ID 就查原任务；提交结果不明无 ID 则待核对，保留原键，不盲重试创建。
- 跨 VM 错误使用结构化状态、阶段和 Retry-After。查询 5xx / 超时 / 429 可重试；401 / 403 等受阻保留恢复入口；上游明确业务失败才 failed。不能用 HTTP 状态码一概决定生成失败。
- Dola queryMedia 不完整下载成片；下载进入公共独立容量控制。补查结果地址网络失败仍可恢复 downloading；上游不支持刷新或已删除结果，明确待核对/无法补取，不保证一定能拿到新链接。已经保存的逐项输出登记，崩溃后认回原文件。
- 重启先恢复已有 ID / downloading，统计上游在途额度后再放新 queued；查询休眠不占本地网络槽，但不得释放上游在途额度后无限提交。
- 同键校验在写入协调范围内重查，逐项返回 accepted / existing / rejected；同参数并发重传、追加都保持身份。无 taskId 不虚报 accepted。
- 源码版本或账户变化不盲查错账户、不删除版本保护；兼容更新可继续，不兼容保持受阻并能恢复原任务。记录凭据引用，不落 Key。
- 限定本轮完整长期恢复能力为当前 Dola 分阶段适配；其他同步供应商遵守原条件项范围，明确能力差异。旧 generateVideo 已说明等待成片，进一步标注长期任务入口，不偷偷改旧返回结构。

### F：Codex 连续操作与网页恢复可靠

- 同连接普通并行命令进入有界 FIFO，只有达到明确容量或等待预算时才给可理解的拒绝；排队取消/超时必须移除，不能稍后偷偷执行。执行前重查 connectionId / directory / canvasId。
- 只读节点状态查询不触发全图 flush。改动画布的命令等待本次合法保存结果；已经受理视频但画布保存失败，分别报告两件事。
- 网页生成收到 taskId 后立即返回，首次进度查询异步。90 秒提交 + 30 秒查询的叠加只存在于网页节点链，服务器 submitVideoTasks 不经过此链，不混修。
- 任务绑定含 directory / canvasId / nodeId / batchKey / itemKey / taskId；首包丢失按原键查回，unknown、空查询、失败的 attach 不清关联。完成但画布未保存时仍可恢复。
- 登录过期保留草稿和任务，统一处理各客户端 401；重新登录只恢复查询。首次 attach 失败后能再次恢复，无 taskId 只 GET 原键、不调用 submit。暂停观察、回前台、网络恢复能够重新启动查询，恢复不依赖重新校验生成提示词。停止浏览器观察不能修改服务器 trackingStatus；服务器暂停跟进必须是不同的明确操作。
- 首次画布保存使用读取内容时的 revision；冲突保留本地草稿。不能为旧内容重新取最新版本，也不能读取失败后降级覆盖。
- 合并同工作区节点查询，复用最多 200 个 taskId 的查询能力；后台可减少任务状态轮询，但不要停止 MCP 控制连接。原有节点布局和使用流程保持简洁。

### C：五类自动清理按真实使用生效

- 逐项列出生成文本、生成图片、生成视频、原始资料和缓存的真实创建/修改/导入入口，接通登记。改名、复制、删除、结果回写、输入复用都要维护归属。

- 成片保留期从可靠落盘与最后实际占用解除的较晚者起算，原始资料依原方案从导入/修改计时；部分输出晚解除保护后仍有完整保留期，普通预览不续期。

### I：共用边界、容量和发布

- 设置保存返回的 revision 对应该次落盘内容；并发等待模型刷新时不能取到另一请求版本。设置冲突有真实的重载/保留草稿入口。
- 父 Agent 让位给子任务后恢复推理必须重新获得额度；异常/取消只释放实际持有的槽。
- FFmpeg 容量放在宿主唯一执行边界，覆盖 HTTP、工具 bundle 和供应商入口；不能以多个 bundle 各自的模块变量充当全局限流。

- compose 模板透传 Secure 配置，与实际 HTTPS 部署一致。线上 Secure 当前已经开启，不能误作紧急关闭/重建理由。
